Interview Edit · 使用说明

从一批本地素材，
到一版可审核的剪辑预览

给第一次使用 Interview Edit 的测试人员。按本文完成安装、环境检查、素材索引、代理、转录、cut-list、预览和质量检查；默认停在预览，不自动生成母版。

适用范围：语音主导的访谈、口播、教程、测评和 Vlog。当前是私测版命令行工具，不是通用非线性剪辑软件。
Guide date
2026.09.04
本地优先原始视频留在本机，CLI 只读源素材。
两个目录素材目录与剪辑项目目录必须分开。
先 Preview先审预览与 QC，再单独决定是否输出母版。
JSON 留证保留命令退出码、run ID 和报告路径，便于反馈。
Executive summary
一页看懂

可以开始私测，但先确认环境和隐私边界

最短路径是：在 Codex 中打开仓库，提供素材目录和剪辑目标，让项目 Skill 调用 CLI；技术用户也可以完全通过命令行操作。

01 · Position

定位：可审核的私测版

适合小范围试用和反馈；没有真实素材验收前，不应宣传为成熟生产工具。

02 · Device

设备：优先 Apple Silicon Mac

媒体链路已在 macOS 和 Linux CI 验证；首批体验建议使用 Apple Silicon Mac。

03 · Privacy

隐私：初始化时必须选择

strict 不让 Codex 读取正文和画面；assisted 允许按需读取局部转录和证据。

04 · Transcription

转录：后端和模型另备

基础安装不含语音识别运行时和模型。任何依赖或模型下载都要由使用者明确同意。

05 · Workflow

流程：默认停在预览

校验失败绝不渲染；预览通过也不等于允许生成母版、冻结版本或公开发布。

06 · Feedback

反馈：给证据，不发原片

反馈系统、命令、退出码、JSON 错误、run ID 和脱敏路径；不要在未经许可时上传素材。

推荐第一次试用只完成一件事：安全地产出一版预览并给出反馈。

  1. 准备：获得私有仓库权限，安装 uv、Python 3.11+、FFmpeg/FFprobe。
  2. 隔离：原始素材与项目产物放在不同目录，初始化时明确 strict 或 assisted。
  3. 处理：先 doctor，再索引、代理、转录；每一步都阅读退出码与 JSON。
  4. 剪辑：通过 Codex Skill 或手工 cut-list 生成预览，随后运行 preview QC。
  5. 停止：预览审核完成即结束首次私测；母版、冻结和发布都要另行授权。
Contents · 使用路径

按六个章节完成第一次试用

  1. 01安装准备检查设备、依赖、仓库权限和本地转录条件。
  2. 02建立项目分离素材与产物目录，选择隐私模式并运行 doctor。
  3. 03用 Codex 剪辑推荐路径：让项目 Skill 按自然语言目标编排 CLI。
  4. 04直接使用 CLI技术路径：逐条执行索引、代理、转录、cut-list 和预览。
  5. 05审核与交付查看预览和 QC；区分预览、母版、冻结三次决定。
  6. 06报错与反馈根据统一退出码处理问题，提交最小且可复现的反馈。
Recommended · 推荐方式

非技术使用者优先通过 Codex + 项目 Skill 操作；CLI 是唯一执行内核和事实来源。

Boundary · 使用边界

本文命令基于 0.6.0 当前工作区；正式分发前应替换为最终提交。模型安装、真实内容读取、母版渲染、版本冻结和外部发布不会从“继续”或“预览通过”中自动获得授权。

Chapter 01 · 安装准备

先把运行环境准备好

首批测试建议使用 Apple Silicon Mac；基础安装可以完成除转录外的全部阶段。

仓库权限 → uv 与 Python → FFmpeg / FFprobe → 基础安装 → 可选转录
01.1

开始前清单

项目要求判断
仓库已获得 guang-tech/edit-CLI 私有仓库读取权限必需
系统首批推荐 Apple Silicon Mac；Windows / NVIDIA 尚未完成本项目验收推荐
运行时Python 3.11 或更新版本，uv，FFmpeg 与 FFprobe必需
磁盘为代理、转录、缓存、预览和 QC 证据预留空间必需
转录MLX Whisper 或 Faster-Whisper，以及已在本地准备好的模型按需
01.2

安装系统工具

如果 Mac 已安装 Homebrew，可用下面两条命令准备 uv 和 FFmpeg。安装会访问网络；在团队设备上先确认软件安装权限。

Terminal · macOS prerequisites
brew install uv ffmpeg
uv python install 3.11

没有 Homebrew？

使用团队认可的软件分发方式。uv 官方安装页与 FFmpeg 官方/Homebrew 包页面列在文末；不要从不明镜像下载可执行文件。

01.3

克隆并安装基础 CLI

Terminal · repository setup
git clone https://github.com/guang-tech/edit-CLI.git
cd edit-CLI
uv sync --locked
uv run interview-edit --version
uv run interview-edit --help

正确结果

版本命令显示 0.6.0，帮助中能看到 init、doctor、status、ingest、proxy、transcribe、sync、cutlist、render、qc 和 version。

01.4

可选：安装 Apple Silicon 转录后端

只有需要本地语音转录时才安装。下面命令可能下载依赖，但不会自动授予模型下载权限。模型应由维护者预先放入本机缓存或提供本地目录。

Terminal · optional MLX backend
uv sync --locked --extra mlx

本步骤未包含模型文件

项目名称或配置中的 tiny 不等于允许下载。没有本地模型时，transcribe 会停止并返回结构化错误。

Chapter conclusion

先确认基础 CLI 能启动，再考虑转录模型

安装失败时不要绕过 doctor，也不要复制别人机器上的未知环境。基础 CLI 与本地模型是两项独立准备工作。

Chapter 02 · 建立项目

素材与工作产物必须分开

源素材是只读输入；索引、代理、转录、渲染和 QC 都写入独立项目目录。

建立两个目录 → 放入素材 → 选择隐私 → init → doctor → status
02.1

准备目录

Read only · 素材目录

只放摄像机、录音和 B-roll 原文件

项目运行后不要移动、重命名或覆盖这些文件。CLI 会读取并校验，不会把产物写回这里。

Writable · 项目目录

只放配置与生成产物

代理、转录、cut-list、预览、运行清单和 QC 报告都位于这里，可与素材盘分开。

Terminal · choose absolute paths
MEDIA="$HOME/Movies/interview-edit-beta/source-media"
PROJECT="$HOME/Movies/interview-edit-beta/my-first-project"
mkdir -p "$MEDIA"

# 现在把测试素材放进 $MEDIA；不要把 $PROJECT 建在 $MEDIA 里面。
02.2

选择隐私模式

模式Codex 可以读取适合代价
strict路径、ID、哈希、时长、状态与统计敏感访谈、保密内容需要你提供明确剪辑区间，不能让 Codex 基于完整语义选段
assisted完成当前判断所需的局部转录、缩略图和 QC 证据希望使用自然语言辅助剪辑被读取的文本或图片可能进入当前 Codex 会话上下文

两种模式都不会授权上传

网络转录、素材上传、模型下载和外部发布始终需要单独说明对象、目的和范围。

02.3

初始化并检查环境

Terminal · initialize assisted project
uv run interview-edit init \
  --project "$PROJECT" \
  --name "第一次私测" \
  --media-root "$MEDIA" \
  --privacy assisted \
  --json

uv run interview-edit doctor --project "$PROJECT" --json
uv run interview-edit status --project "$PROJECT" --json
EXIT 0

环境可继续

仍应阅读 warnings；成功只说明没有阻塞条件，不代表剪辑质量已通过。

EXIT 4

缺少依赖

最常见是本地转录后端或模型未准备。基础媒体阶段可能仍可用，但不要直接运行 transcribe。

EXIT 5

路径或权限不安全

停止并修正目录边界或访问权限，不要用更宽权限掩盖问题。

Chapter conclusion

doctor 是正式入口，不是可跳过的诊断工具

把 doctor 的 JSON 保存下来。只有实际检查到的 Python、FFmpeg、FFprobe、编码器、字体、路径和转录条件才能作为当前机器证据。

Chapter 03 · 用 Codex 剪辑

推荐：用自然语言驱动已验证的 CLI

Codex Skill 负责理解剪辑目标、检查项目状态和组织命令；真正的媒体处理仍由 CLI 完成。

打开仓库 → 提供项目路径 → 说明目标与边界 → Skill 检查状态 → 生成预览 → 人工审核
03.1

在 Codex 中开始

  1. 在 Codex 中打开 edit-CLI 仓库，确保项目级 interview-edit Skill 可被发现。
  2. 授权 Codex 读取素材目录、写入项目目录；不要把素材复制到代码仓库。
  3. 告诉 Codex 项目绝对路径、视频类型、目标时长、必须保留和禁止出现的内容。
  4. 明确隐私模式，以及是否允许读取局部转录、缩略图和 QC 证据。
  5. 第一次任务明确写“只生成预览，不生成母版，不冻结版本，不下载模型”。
03.2

可直接复制的首次任务

Codex prompt · assisted mode
请使用仓库中的 interview-edit Skill。

剪辑项目路径：请替换为我的项目绝对路径
内容类型：访谈 / 口播 / 教程 / 测评 / Vlog
目标：请写清目标时长、受众和叙事重点
必须保留：请列出关键观点、步骤或披露信息
禁止内容：请列出隐私、口误、空镜或不能发布的内容

请先读取配置并运行 status；环境有疑问时再运行 doctor。
在 assisted 模式下，只读取完成当前判断所需的局部转录和证据，并先告诉我。
请依次完成索引、代理、已有本地模型条件下的转录、cut-list 校验、预览渲染和 preview QC。
任何依赖或模型下载都先停下请求许可。
这次只交付预览与问题清单：不要生成母版，不要冻结版本，不要上传或发布。
03.3

不同视频类型要补充什么

类型应补充的剪辑要求优先检查
访谈人物主线、问题顺序、不可断章取义的回答上下文与说话者含义
口播开头钩子、核心观点、CTA 是否保留节奏与重复表达
教程先决条件、步骤顺序、屏幕操作或关键画面不能因压缩时长破坏步骤依赖
测评证据、优缺点、商业披露和最终结论结论是否仍有证据与限制条件
Vlog事件顺序、时间跳跃、环境镜头和情绪节点时间关系是否自然且明确
03.4

Codex 应交回什么

Edit evidence

剪辑版本

cut-list 路径、范围、主要保留/删除/重排，以及没有满足的要求。

Render evidence

预览证据

输出路径、时长、run ID、缓存情况与源素材完整性状态。

QC evidence

质量检查

QC 状态、警告、对应片段和建议动作；不能只说“通过”。

Chapter conclusion

Skill 负责决策编排，CLI 负责事实与执行

若 Codex 提议临时拼接 FFmpeg、跳过 cut-list 校验、降低 QC 阈值或直接修改源视频，应立即停止并反馈。

Chapter 04 · 直接使用 CLI

技术用户可独立跑完整预览链路

下面每条命令都会输出一个 JSON 文档；不要忽略非零退出码，也不要把“产物存在”误认为命令成功。

ingest → proxy → transcribe → cutlist → validate → render preview → qc preview
04.1

索引素材并生成代理

Terminal · ingest and proxy
uv run interview-edit ingest \
  --project "$PROJECT" \
  --full-hash \
  --json

uv run interview-edit proxy build \
  --project "$PROJECT" \
  --resume \
  --json

uv run interview-edit status --project "$PROJECT" --json

为什么首次建议 full-hash

它会记录完整源文件 SHA-256，便于私测结束时证明原片未变化。大素材会增加首次扫描时间。

04.2

运行本地转录

只有 doctor 已识别本地后端和模型时执行。--resume 会复用校验有效的分块结果；不要用 --force 作为默认选项。

Terminal · local transcription
uv run interview-edit transcribe \
  --project "$PROJECT" \
  --language zh \
  --resume \
  --json

退出 3 或 4 时不要原样重试

先读 JSON 中的 error.code。模型名缺失、本地模型不存在或后端未安装，都需要修复实际条件，而不是连续重跑。

04.3

建立 cut-list

从 ingest 返回的索引路径打开 media-index.json，找到准备作为主讲素材的 asset_id。有校正转录后，用它生成按时间顺序的初始骨架。

Terminal · transcript scaffold
ASSET_ID="asset_请替换为媒体索引中的实际ID"

uv run interview-edit cutlist scaffold \
  --project "$PROJECT" \
  --asset "$ASSET_ID" \
  --json

scaffold 不是自动成片

它只把校正后的转录分段转换为确定性时间骨架，不会自动判断叙事优先级。应在 Codex 辅助或人工编辑后再校验。

04.4

校验、渲染预览并做 QC

Terminal · preview gate
CUTLIST="$PROJECT/cutlists/revisions/cutlist-v001.yaml"

uv run interview-edit cutlist validate \
  --project "$PROJECT" \
  --cutlist "$CUTLIST" \
  --profile preview \
  --json

uv run interview-edit render \
  --project "$PROJECT" \
  --cutlist "$CUTLIST" \
  --profile preview \
  --resume \
  --json

uv run interview-edit qc \
  --project "$PROJECT" \
  --policy preview \
  --json

首次 CLI 私测在这里结束

打开 render 返回的 outputPath 观看预览，再结合 QC 报告记录问题。preview QC 的 warning 需要人工判断，不能因为退出码为 0 就自动忽略。

04.5

多机位素材的附加步骤

先用 camera-map 在 ingest 时为每个文件标记 camera_id 和 take_id，再以一台机位为时间零点进行同步。低置信度结果需要人工审阅，不能静默接受。

Terminal · camera sync
uv run interview-edit sync \
  --project "$PROJECT" \
  --take take-01 \
  --reference-camera wide \
  --visual-check \
  --json
Chapter conclusion

顺序不可随意跳过：每一层都依赖上一层的当前证据

源文件或配置变化后，旧代理、转录、同步、cut-list 或 QC 可能失效。继续工作前先看 status 的 validity 与 reasonCodes；实际缓存复用仍由后续命令按完整缓存键校验。

Chapter 05 · 审核与交付

预览、母版与冻结是三次不同决定

首次私测默认只交付预览。后续动作必须绑定准确的 cut-list、render run 和 QC 证据。

观看预览 → 阅读 preview QC → 修改并重跑 → 明确批准母版 → release QC → 明确批准冻结
05.1

预览审核清单

Editorial

内容与叙事

是否断章取义；教程顺序是否正确；测评证据与披露是否保留；Vlog 时间关系是否清楚。

Pacing

节奏与连续性

重复表达、长停顿和跳剪是否合理；机位切换、B-roll 和转场是否遮挡重要信息。

Text

字幕与图文

人名、术语、混合中英文、断句、字体缺字、安全区和标题时长是否正确。

Technical

声音与画面

检查黑场、静音、音量、峰值、时长差、画幅、帧率和每个切点附近的证据图。

05.2

三道授权门

动作必须先有本次授权不包含
预览当前代理与通过校验的 cut-list母版、冻结、上传、发布
母版人工审核过的预览/QC，以及准确 cut-list 版本冻结、上传、发布
冻结准确 master run、通过的 release QC 和再次明确批准公开分发或替代另一个 run

不要把“预览没问题”解释成发布授权

母版会使用原始素材并执行正式音频处理；冻结会创建不可覆盖的版本证据。两者都不是首次私测的默认步骤。

05.3

确有授权时的正式链路

下列命令只用于已经明确批准的准确版本。把实际 master run ID 填入 MASTER_RUN，release QC 通过后再次确认，才执行 freeze。

Terminal · authorized release only
uv run interview-edit cutlist validate \
  --project "$PROJECT" --cutlist "$CUTLIST" --profile master --json

uv run interview-edit render \
  --project "$PROJECT" --cutlist "$CUTLIST" --profile master --resume --json

MASTER_RUN="render_请替换为实际runID"
uv run interview-edit qc \
  --project "$PROJECT" --run "$MASTER_RUN" --policy release --json

# release QC 通过并再次获得冻结授权后，才运行：
uv run interview-edit version freeze \
  --project "$PROJECT" --run "$MASTER_RUN" --approve --json
Chapter conclusion

交付的是证据链，不只是一个 MP4

预览或母版都应能对应到 cut-list、配置、run manifest、输出哈希和 QC 报告。没有这些绑定关系的文件不能作为可复现交付。

Chapter 06 · 报错与反馈

根据退出码处理，不要重复碰运气

失败时保留 JSON 和已生成的有效证据。修正真实原因后再运行，不删除缓存来制造“干净结果”。

退出码 → error.code → 对应输入或环境 → 一次有依据的重试 → 最小反馈包
06.1

退出码速查

退出码含义正确处理
0命令成功继续阅读 warnings 和生成的证据，不代表内容审美已通过
1一般运行错误先看 status.latestRun 与 artifacts/logs 下的运行清单；只在有明确变化时重试一次
2参数、配置或结构错误修正准确参数或 YAML/JSON，不能原样重试
3预检、cut-list 校验、同步置信度或 QC 失败阅读 issues，修正输入并生成新的证据
4缺少外部依赖运行 doctor；安装依赖或模型前先获得许可
5路径或权限边界失败停止并修正目录/权限，不扩大访问范围绕过检查
130用户中断保留终止清单；仅对支持 resume 的阶段恢复

第一次交给他人使用，目标不是“直接出片”，而是完成一条安全、可复现、可反馈的预览链路。

只要测试者能在自己的机器上通过 doctor、保持源素材不变、生成通过校验的预览、阅读 preview QC，并提交可复现反馈，这次私测就有效。真实转录质量、长视频性能、生产编码格式、母版与公开分发需要后续独立验收。
