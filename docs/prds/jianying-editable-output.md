# 剪映可编辑交付需求补充

日期：2026年9月8日。
用户方向：自动剪辑后还要能继续调整，优先交付剪映草稿；Mac 与 Windows 均为目标平台。

## 产品变化

当用户需要后续手工调整时，交付对象应包含剪映原生工程，而不只是压平后的 MP4。
视频切段、主音轨、B-roll、图片、标题和字幕需要保留为可单独编辑的轨道或片段。
用户在剪映里完成精修，再由剪映导出成片。

这项要求扩展了早期 PRD 中对 NLE 工程导出的排除范围，限定为剪映交接，不改变本地优先、
原片只读和 CLI 统一执行的原则。FFmpeg 预览继续保留，供快速检查和对照。

## 第一阶段交付

1. 从当前剪辑清单生成 Mac/Windows 草稿入口与素材登记信息。
2. 默认打包引用的完整原片、图片和字体，允许先查看空间估算。
3. 文字保持原生文本，允许在剪映中改内容、样式和位置；不将文字烘焙成不可修改的画面。
4. 机位切换沿用已有同步证据，B-roll 不取代主音轨；基础淡入淡出保留为可编辑关键帧。
5. 检测剪映安装位置，并提供明确的草稿库安装命令，始终创建新草稿，不覆盖用户工程。
6. 交付结构校验、来源清单和安装说明；不把“写出了 JSON”当作原生客户端验收。

## 当前验收边界

用户尚未安装剪映，因此当前只能验证草稿生成、素材映射和文件安装行为。后续必须在
实际 Mac/Windows 剪映版本上打开草稿，确认素材不丢失、文字可编辑、切点/机位/音轨正确，
保存后重新打开，并从剪映导出短片，才能记录该版本通过原生验收。

字体、画面叠加和声音处理在两种渲染器之间可能不同，需要预览复核。剪映内的人工修改
由剪映保存，不自动同步回原剪辑清单；现有 CLI QC 不覆盖人工改动后的原生成片。
第一阶段不包含对加密草稿的读取、回写或原生 GUI 的无人值守自动导出。

验收与接口细节见 [剪映草稿契约](../specs/jianying-draft-v1.md)。

## 正确性补全与操作入口

草稿必须绑定生成时的清单与素材版本；即使文件哈希自洽，错误的素材引用、时间范围、
字幕文本或双端时间线也必须阻止安装。大素材可选择复用已校验的完整文件缓存，提供进度，
中断后不交付半成品。

交接入口包括草稿验证、客户端与版本检测、自定义草稿位置、启动应用，以及剪映导出后
的视频完整解码/时长/画幅/音轨检查。成功状态必须区分文件检查、启动请求和真实客户端
验收；不能用前两项冒充第三项。手工调长/剪短后检查视频时，应显式提供新的预期时长。

用户确认 Windows 当前无法实机验证，两端仍为支持目标。Mac 安装需要用户明确同意；
客户端尚未安装时，保留实验状态，不能宣称已经完成打开、编辑、保存重开与原生导出。
