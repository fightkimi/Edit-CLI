## FFmpeg capability test

FFmpeg advertised `videotoolbox`, `libx264`, `libx265`, ProRes, and AAC support.

A real 12.012-second, 640x360, `30000/1001` H.264/AAC synthetic file was generated in `/private/tmp/interview-edit-m0-smoke` and probed successfully:

- libx264: passed in the Codex sandbox; output size 1,310,213 bytes.
- h264_videotoolbox: failed in the Codex sandbox with compression-session error `-12908`.
- h264_videotoolbox: passed on the host; output size 2,999,985 bytes.
- Audio stream: AAC, 48 kHz, stereo.

Conclusion: hardware acceleration must be validated with a real probe in the current execution environment. `libx264` is the required portable fallback.

## Local transcription test

No MLX Whisper, Faster-Whisper, Torch, MLX, CTranslate2, Whisper CLI, or cached model was present before the test.

After explicit approval, M0 installed `mlx-whisper` 0.4.3 in the project environment and downloaded `mlx-community/whisper-tiny` to a temporary Hugging Face cache. A synthetic Chinese voice generated by macOS `say` was converted to 16 kHz mono WAV and transcribed locally with word timestamps.

Actual host result:

```json
{
  "text": "您好,这是一段本地主要入依色事今天我们试试采访解析工具",
  "language": "zh",
  "segmentCount": 2,
  "wordCount": 23
}
```

The tiny model's wording was inaccurate, which is expected for a smoke model and synthetic voice. The test establishes executable local inference and timestamp output, not production transcription quality.

Additional observations:

- Passing the downloaded snapshot's absolute path completed a forced-offline run in 1.41 seconds on the host.
- Passing a remote model ID while `HF_HUB_OFFLINE=1` still initialized the current Hugging Face HTTP client and encountered the machine's SOCKS proxy configuration. Production offline operation must resolve and persist a local snapshot path before inference.
- MLX import failed inside the Codex sandbox because no Metal device was exposed.
- MLX import succeeded on the host; a cold import in a fresh environment took 34.59 seconds.

Conclusion: MLX Whisper is the preferred Apple Silicon backend. Codex-driven transcription needs an approved host execution context with Metal access. `doctor` performs a real backend import with a 60-second cold-start allowance instead of trusting package discovery.

## Reference implementation findings

The reference repository validates useful production methods: cut-list-driven assembly, multi-window audio correlation, evidence images, silence/edge scans, source-use ledgers, loudness normalization, and immutable version directories.

It is not suitable as a runtime base without reimplementation because it contains hard-coded project paths and content, Windows executables, fixed camera/take mappings, NVIDIA encoding, float-second edit data, mutable module globals, and direct process exits. M1 therefore reuses behavior and lessons, not source code.

## M0 decision

The host can run the required media and local-transcription foundations. M1 can proceed with Python 3.12, `uv`, FFmpeg/FFprobe, MLX Whisper on Apple Silicon, runtime hardware probes, portable software fallbacks, and adapter boundaries.

Not validated in M0:

- Production-size Whisper models or real Chinese interview accuracy.
- NVIDIA CUDA, Windows, or Linux execution.
- Multi-hour media throughput, thermal behavior, or disk estimates.
- Ingest, synchronization, rendering, QC, and freeze behavior; these belong to later milestones.
