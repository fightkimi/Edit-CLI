# video-use 对本项目的参考价值

评估日期：2026-10-08。结论：**值得参考，优先移植剪辑决策与成片复查方法，保留现有 CLI、
cut-list、来源校验和剪映导出适配。** 本轮是源码评估，没有改产品代码、安装外部技能、上传
素材或执行云转写，也没有进行真实素材的质量 A/B 测试。

## 证据与现状

外部基线：[browser-use/video-use](https://github.com/browser-use/video-use/tree/b877063835e6ea6e457124da7e28a0ae26691dc3)，
提交 `b877063835e6ea6e457124da7e28a0ae26691dc3`，提交日期 2026-09-24。
本轮通过 GitHub API 与临时只读源码副本核对了该版本。下列外部证据均为 T1：项目自身源码、
测试与文档；文档中的效果描述不等于本项目的实测效果。

内部基线：本地 `c01a5a4` 的产品代码，先前已通过两个 PR 合入两仓库主分支；本次未查询
远端后续变化。当前已有本地逐词转写、中文分句、词内切点检查、多机位同步、分段缓存、
源素材验证、预览/master 分离、响度与峰值 QC，以及实验性可编辑剪映草稿。
剪映实机验收按用户要求保持暂停。

## 有价值但不能直接搬过来的部分

1. **云转写并非接入前提。** 它的 [transcribe.py](https://github.com/browser-use/video-use/blob/b877063835e6ea6e457124da7e28a0ae26691dc3/helpers/transcribe.py#L84)
   会上传音频到 ElevenLabs Scribe。我们应先复用已有本地逐词转写；以后如增加云适配，需要
   独立的用户授权、成本和隐私边界。说话人/笑声等信息有价值，但不能在缺少检测时自动补造。
2. **缓存不能降级。** 上游同一文件名/音轨的转写文件存在就返回，没有在此路径中核对原片
   指纹与转写参数；源文件被替换后存在复用旧稿的风险。这是源码可见的风险，本轮未运行
   反例。保留我们已有的 source fingerprint、模型参数、输出摘要和失效检查。
3. **波形图不是声音验收。** 上游 RMS 包络按每个窗口自己的最大值归一化，不能据此比较
   两段绝对音量；音频提取失败会返回零数组，也不能被我们解释成“真实静音”。声音是否自然
   仍需试听，幅度图与数值只能提供诊断证据。
4. **自评循环主要是 Skill 指令。** 其要求检查输出、修复后重渲染，并限制轮数；源码清单
   没有一个端到端的自动自评服务，`timeline_view --edl` 也明确尚未实现。我们可以借鉴有界
   修订，但应把问题、证据、修改和复查结果写入现有运行记录，不能仅靠一句“AI 检查过”。
5. **渲染规则需要按真实管线判断。** 它的 extract 阶段编码视频，有叠加/字幕时 composite
   阶段又编码；`-c copy concat` 只代表拼接步骤不重编码。不能把它推导成整条流程无损或
   必然比现有渲染清晰。我们已经在单个片段内先叠加再放字幕、按输出时间偏移叠加层，并
   有缓存与最终响度处理，这些无须重新做一套。
6. **不能直接补齐剪映编辑。** 当前 helper 的交付是 MP4、字幕与自身 JSON EDL；检查到的
   文件中没有剪映草稿导出/导入适配。该项目对剪辑质量有参考价值，但不提供我们尚未完成的
   剪映客户端打开、保存重开、原生导出验收证据。
7. **协议和文件位置仍用本项目规则。** 上游 EDL 用浮点秒，默认输出位于素材文件夹内的
   edit 子目录；我们必须继续用整数微秒，产物放在独立 artifact root。不得直接复制其
   全局 Skill 并让 helper 绕过现有 CLI。严格隐私模式也不应自动向模型暴露逐字稿或图像。

## 成熟度与可复用边界

该版本提供 6 个 Python helper 和动画指导资料，定位是编码代理驱动的剪辑工作流。
本轮静态统计 3 个测试文件、26 个 test 方法，集中在字幕、帧率与旋转方向；**没有运行这些
测试**。这个范围不能证明跨平台端到端渲染、声音听感或中文长视频质量。

仓库根 [LICENSE](https://github.com/browser-use/video-use/blob/b877063835e6ea6e457124da7e28a0ae26691dc3/LICENSE)
标为 MIT。若后续复用源码，应固定版本并保留版权和许可记录；本轮没有将源码复制进产品。
外部动画引擎是独立依赖，不能因这个仓库的 MIT 许可就假定所有引擎、字体与素材使用条件相同。

## 假设结论与反面证据

- **“能改善选段与节奏判断”**：方法与 helper 支持这个方向；是否改善我们的真实成片仍待
  同素材对照，不能给出质量提升百分比。
- **“可直接替代现有底层”**：不建议。当前产品在素材来源、跨平台文件交接、类型化协议、
  QC 阻断和原片保护上已有明确约束；整套切换会丢失必要边界。
- **“接上它就能继续在剪映里调”**：不成立；它没有相应原生适配。
- **“加了 Skill 就等于获得成品质量保证”**：不成立。部分能力是工作指引或外部工具调用，
  仍需要本项目实现、自动检查与人工画面/声音复核。

反面观点是先做动效最容易产生可见变化。但当前用户反馈同时涉及脚本、切点和整体效果，
动效不能修复错误选段、断字和音量不连续；优先把编辑判断所需证据做完整更符合当前问题。
另一个观点是直接换云转写获得全部新能力；它可以作为以后可选适配，但短语索引、证据图与
大部分复查能力并不依赖更换转写供应商。

## 建议的首轮优化包

范围：**跨素材短语阅读视图 + 切点画面/波形/词级证据 + 受控语音边界处理 + 字幕阅读节奏**。
先不引入整套动画运行时，不改现有 QC 通过条件，不重启已暂停的剪映实机验收。

验收使用同一批素材和同一份编辑目标，对照旧版与新版：

- 每个选段都能回溯到素材与原文时间范围；重复 take 的选择有可查看的依据。
- 切点证据在源时间与输出时间间正确对应，丢音轨/解码失败不会被当作静音。
- 防点击处理不改变时间线总长，不损伤短词，不打断连续主音轨；做数值检查及试听。
- 字幕文字完整、没有越界/重叠，短促提示与长句分别符合显示时长约束。
- 整体叙事、开头、停顿与听感以人工盲看/试听比较，不用测试数量替代质量判断。

只有这组结果证明收益后，再扩展色彩匹配和可选动效。以上命令/能力是建议范围，尚未实现。
